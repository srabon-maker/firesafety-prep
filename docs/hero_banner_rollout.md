# Hero banner rollout

No additional SQL migration. Existing homepage_content.image_url and publication settings are reused. Deploy reviewed main via cPanel. The deployment explicitly creates uploads/homepage and installs its .htaccess and the upload helper before copying the updated admin page. Ensure PHP fileinfo and GD (JPEG/PNG/WebP support) are enabled, upload_max_filesize >= 4M, post_max_size > 4M, and directory is writable by the PHP process. Apache must honor .htaccess directives; verify in staging.

Admin requires existing authentication and CSRF. Select banner/announcement, write title and description, choose optional existing first-party image URL or a new JPG/PNG/WebP file (up to 4 MiB, 4096 per dimension and 8 MP). New upload is decoded and re-encoded as JPEG, longest side <=1600 pixels; original metadata and filename discarded. Transparent pixels are flattened to white. Use 1200x600 artwork with important content away from the bottom text overlay. Select publish explicitly. Unpublished rows are not listed by the public API; uploaded assets themselves are public if their random URL is known. Do not upload confidential material. Replaced files are retained deliberately (rollback/old links); no automatic deletion.

Check: unauthorized admin requests redirect; invalid CSRF rejected; valid JPG/PNG/WebP upload returns first-party random .jpg URL; fake image, PHP, SVG, oversized and over-resolution files rejected; try bad upload and confirm existing content unchanged. Confirm directory listing/script URLs are denied and actual image can be read with image/jpeg. Confirm public API contains only published banners, admin can unpublish/edit and preserve previous URLs. Existing banners remain compatible. App requires new Codemagic APK for full-width carousel; subsequent content updates require refresh only. Check one/zero/multiple banners, swiping, dots, pause, five-second auto-advance, reduced motion, backgrounding, other tabs and banner dialog/target. No live tests or release build performed by this PR.
