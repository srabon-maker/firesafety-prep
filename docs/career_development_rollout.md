6. Directory: explicit opt-in, user-entered fields only, registered viewers; no contact details. Optional photo: the mobile picker resizes large gallery images to a maximum 720 px per side. Server accepts JPEG/PNG/WebP up to 2 MiB and 2048 px per side, decodes and re-encodes as JPEG at up to 720 px and 200 KiB (strips metadata). Enable PHP GD (JPEG, PNG and WebP support), ensure POST limits allow 3 MiB, and verify the private-photo migration before deploying. Photos are stored transactionally in career_profile_photos and served by the authenticated API, never as public upload files. Only the owner and admin can view a pending photo; other registered viewers can view approved photos. Test replacement, removal, hide/reject, logout, and account deletion using separate accounts. If any old prototype images exist in uploads/profiles, remove them securely after backup and verification; never serve them publicly. Approval required after each edit; hide immediately. Verify second account cannot see pending/hidden and cannot modify another profile. Account deletion cascades. Admin approval is moderation, not professional verification.
7. Verify API unauthenticated 401, invalid actions 422, pagination and empty states. Test actual APK and live DB before release. No production data seeded.
