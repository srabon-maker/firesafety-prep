# Central category management (compatible with existing data)
Admin Category Management now has Question, Note and Model Test tabs. Create in all three sections creates any missing active ROOT category with the exact same name in a transaction. It refuses ambiguous/inactive/subcategory collisions; it does not merge, rename or reassign existing records. IDs remain type-specific: legacy questions reference category text, notes and model tests reference IDs. This is a shared admin workflow, not a single-ID taxonomy migration. Subcategories can be managed separately by type. Question admin offers central names as suggestions (including bulk import), retaining historical names. Model test builder already restricts manual/random source questions by the test category's exact name; mixed test remains supported. Published tests API now supplies category_id/name and app filters currently returned tests (existing API limit 100). Existing active attempts remain outside the category filter. Category activation is for admin selection; it does not automatically unpublish content. Category deletion is blocked when content references the ID/name. Before deployment verify live categories.category_type accepts 'test' (existing model test code already assumes it); if the live schema differs, inspect SHOW CREATE TABLE categories before changing it. No new SQL migration is required for a compatible schema. Deploy backend via existing cPanel allowlist and build APK. Test shared creation, duplicates, each admin picker, published question/note/test navigation, mixed tests, attempts, category deletion guard, and legacy data.
