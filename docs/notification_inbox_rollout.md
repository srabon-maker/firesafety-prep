# Notification inbox rollout

Uses the existing notifications table, including user_id, title, message, notification_type, is_read and sent_at. No required new migration for the supplied schema. Verify live schema and InnoDB; for large inboxes consider a reviewed composite index (user_id,id) and unread index after EXPLAIN. Only rows with sent_at <= NOW() and non-null sent_at are published. Existing Admin Operations writes these values.

GET /api/notifications/index.php returns at most 25 rows newest ID first, unread_count and next_before_id. POST JSON mark_read with id or mark_all_read with through_id uses authenticated account scope. Mark-all covers published rows up to the newest loaded ID, not newer arrivals. IDs are decimal strings. Both actions are idempotent. Missing/foreign ID returns 404; expired token 401. Responses no-store; no user IDs or tokens in response. No deletion or arbitrary links/actions.

Home bell uses AuthGuard; Profile links to inbox and retains local preferences separately. Inbox has refresh, pagination, read/unread, detail, mark all, loading/empty/error states, Bengali/English labels. No push, background delivery, home badge, or preference syncing/filtering; notification text is displayed as supplied by admin. Date uses database server timestamp. No durable client inbox cache.

Unauthenticated endpoint must return JSON 401.
